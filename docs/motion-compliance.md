# 動作の実測チェック

生成計画には ARDY の動作区間に加えて、原文で指定された測定可能な動作の checks を含めます。Codex / OpenAI API / Claude API が同じ計画関数を使います。追加の AI 呼び出しはありません。

現在の対象は移動・両足ジャンプ・腰を落とす動作・手を顔付近の高さへ上げる動作です。チェックは各計画区間に割り当て、生成された全体の長さに合わせて時間を換算します。最大20Hzでアバターの実際の関節位置を調べ、アバターの身長に対する閾値で判断します。単一フレームのノイズを成功にせず、隣接する2フレームを要求します。

3候補モードでは全候補の測定項目が同じで、すべて測定できた場合に検出数を優先します。足滑り・沈み込み・動作消失の既存ゲートは維持します。指示動作の検出数が同じ場合は既存の物理指標で比較します。自動修正は既定でOFFのままです。直接修正では、元は検出できた動作が検出されなくなる候補を自動採用しません。

## 限界

これは幾何学的な代理指標です。2歩か3歩か、移動方向、到達位置の精密さ、パンチの技術、感情、自然さ、衝突や物理的安定性までは検証しません。手上げは高さ、ジャンプは両足の高さを見ており、正しい演技であることの保証ではありません。計画した区間もAIによる推定です。項目なし・測定不能を成功とは扱いません。

履歴の再生では現在のアバターで再測定します。画面の「計画AI」は成功した計画リクエストに使った提供元・指定モデル・完了時刻を保存したものです。Codex利用枠の％だけから呼び出しの有無を推定しません。

## 検証

- 単体テスト: 静止と移動、片足上げと両足離地、単一フレームのノイズ、しゃがみ、左右の手、区間の取り違え、測定不能、候補選択、修正での検出消失。
- ブラウザーの模擬AIテスト: 未検出表示・提供元表示・4言語・生成と修正の互換性。
- tools/compliance-live.mjs: 実際のCodexサブスクリプション経由で gpt-6-astra を呼び、ARDY生成とアバター上の実測を実行。--candidates で3候補を検証。これは利用枠を消費する明示的な実行用スクリプトです。
