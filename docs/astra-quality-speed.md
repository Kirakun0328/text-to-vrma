# Astraの設計能力と生成速度（2026-09-21）

## 公式情報と用途の切り分け

調査対象は **GPT-6 Astra (`gpt-6-astra`)**。別モデルへの置き換えは行っていない。

- [公式モデル情報](https://developers.openai.com/api/docs/models/gpt-6-astra): 複雑な推論、コーディング、調査、コンピューター操作などを対象とし、テキスト・画像入力、構造化出力、ストリーミングを利用できる。音声・動画をそのまま受け取るモデルではない。モーション合成専用の品質指標は示されていない。
- [モデル利用ガイド](https://developers.openai.com/api/docs/guides/latest-model): 複数条件の保持を生かし、範囲・出力形式・曖昧さの扱いを明示する。リアルタイム計画では追加質問をせず、明示条件を守って未指定部分を補う。推論はlowを維持し、非対応のnoneやtemperature等を追加しない。
- [Astra向けプロンプト再検討](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra): 重複した手順や不要な指示を減らし、仕事に必要な条件へ絞る。本実装でも主動作に関係しない身体説明を増やさない。
- [遅延最適化](https://developers.openai.com/api/docs/guides/latency-optimization): 出力の短縮、ストリーミング、独立処理の並行化を重視する。入力文を短くしただけで大幅な高速化を保証しない。

能力の生かし方は、自由文から動作順・左右・回数・同時動作・終止姿勢・移動制限を設計し、身体／頭／視線／表情の責任を分けること。Astraが設計した文章をARDYが必ず忠実に実現するとは限らないため、実行可能な制約は数値化して生成側でも適用する。画像理解は描画結果の品質評価に使えるが、毎回の初動に画像レビューを追加すると待ち時間が増えるため、通常生成には追加していない。

Responses APIの非同期ツール呼び出しや推論設定変更を、既存のCodex app-server接続が自動で利用できるとは扱っていない。有料Fastモードへの無断変更も行わない。現在の経路では最初の完成区間を待ち、ARDYによる生成と残りの設計を重ねる。

## 今回の変更

1. **信頼された設計ルールと入力データの分離**。逐次生成のsystemメッセージをCodexの`baseInstructions`に置く。ユーザーの文章をsystem指示へ昇格させない。通常生成ごとの独立性は維持する。
2. **表情曲線の可逆な短縮**。中立は`[]`、行末のゼロは省略可能とし、受信時に元の5表情ウェイトへ展開する。曲線の間引きや品質設定の低下ではない。旧形式も読める。
3. **身体用captionの整理**。明示された動作と条件を直接記述する。通常動作を勝手に腕・脚などの副動作へ展開しない。左右・回数・複合動作・終了条件は省略しない。位置の固定はrootAxesで守り、身体captionへ静止を連想させる重複した移動禁止文を渡さない。特定プロンプトへの分岐や動作例の埋め込みはない。
4. **移動軸の制約**。区間ごとの`rootAxes: [x,y,z]`で許可する平行移動を指定する。水平移動を禁止しても上下動・骨盤回転・脚運動の自由度は維持する。出力を補正してから次の生成履歴へ再エンコードする。骨盤を動かす場合に全フレームへ固定軌道の条件入力を与えると歩行自体が弱まったため、その方法は採用しない。過去に再生した区間は変えない。旧形式のroot所有権とARDY単独経路は維持する。足の接地や歩幅の正しさを保証する機能ではない。

JevはAPIキーがある場合の任意の文脈補助で、主設計はAstra。今回の実機評価では実Jevキーを使用していないため、Jev利用時の遅延や精度は測定していない。

## 比較から採用しなかった変更

`tools/ardy-caption-start-eval.py`は、同じ評価専用seedで歩行・しゃがみ・手振りのcaptionと立ち姿の初期履歴を比較する。固定seedは本番生成には導入していない。

- 詳細な歩行captionでは腕を頭上まで上げる動きが出た。主動作だけのcaptionではこの過剰動作が減ったが、歩幅が小さくなる例もあった。
- 立ち姿の初期履歴はしゃがみ始めを改善した一方、歩行を弱めた。また明示された座位や床上姿勢を壊すため、一律の初期履歴固定は採用していない。
- 単純な文章短縮や固定姿勢だけで、すべての動作の品質が上がるとは結論していない。

評価用ファイル・画像: `release/ardy-caption-start-eval/`。単一seed・少数例であり、統計的な品質評価ではない。

## 日本語の入力

短い指示にも対応する設計であり、ユーザーが関節を列挙する必要はない。狙いがある場合は「主動作 → 必要な速さ・範囲 → 終わり方」で書くと曖昧さを減らせる。

- その場でゆっくり歩き続ける。前後には移動しない。
- 左手を一度振って下ろす。その後、右を向く。
- ゆっくりしゃがみ、低い姿勢を保つ。
- 好きな相手に褒められて、嬉しいけれど照れくさい。一度視線をそらし、小さく微笑んで相手へ視線を戻す。

最後のような感情・関係・時間変化を含む文はJevの補助情報も生かしやすい。ただし「お礼を伝える」から必ずお辞儀を追加するような固定の対応は設けない。

### 最終の移動制約

移動軸の固定を全フレームの条件入力に与えた版（`release/astra-root-axes-eval/`）では、両大腿の平均角速度が約2.6〜2.7度/秒となり、画像でもほぼ静止した。その方法は採用しない。生成後の補正だけに変えた版（`release/astra-final-eval/`）でもcaptionに「in place」を残すと歩行が弱い例が出た。

最終版ではAstraが主動作をcaptionへ、位置制限をrootAxesへ分離する。`release/astra-spatial-final-eval/`で「その場で歩く」を実生成した結果:

- 初動7.98秒、完了10.60秒（6秒分、Node VRMA構築）。再生開始後のバッファ不足0秒。
- 水平移動範囲X/Zとも0m。上下の変動約0.051m。
- 左右大腿の平均角速度約38.4／39.6度/秒。正面・側面画像で交互の脚運動を確認。過剰に腕を頭上へ上げる動きは出なかったが、腕を腰に構える傾向が残った。
- 設計・生成の単発測定で、seedも異なるため、これだけで一般的な品質向上率や速度改善率は出さない。足の滑り、厳密な動作回数・終止姿勢、自然な腕の構えは引き続き検証課題。
