# 長尺モーションの指示追従（2026-09-23）

対象症状は「後半で指示と違う動きになる」。現行のAstra→ARDY連続生成を、実Astra low・実ARDY Core40（mini encoder、8 steps）で確認した。Jevはこの評価では未使用。

## 確認した原因と範囲

20秒の入力でも、後半の区間・順序・時刻はサーバーへ届いていた。通信成功や最後までの生成は、指示追従の成功を意味しない。再現した問題は、ジャンプ中に上げた腕が下がる、しゃがんだ後に腕が前へ出た姿勢を保持する、最後のお辞儀が浅い／立ち姿に戻る、という身体出力の違いだった。

ARDYには各区間の文章が2秒の推論窓ごとに渡る。文章だけでは全体の物語や経過時間を知れず、同じ文章に繰り返し動作・完了・保持を詰めると、意図しない段階が再び生成されうる。また、非対象部位とbody=0が保持するのは「実際に生成された姿勢」であり、文章で要求した理想姿勢ではない。

## 変更

`src/realtimePlan.js`のストリーミング設計指示を改訂した。

- 動作名だけでなく、その動作を見分けるための身体の動き・方向を簡潔に記述する。
- 全区間と最後の動作の時間を先に割り当て、各区間の文章だけで意味が通るようにする。
- 順次動作、繰り返し、要求された完了、明示的な姿勢保持を意味のある境界で分ける。
- 区間内で継続する反復と、全体として有限のシーケンスを区別する。
- 指定された保持は到達動作の後に置く。短い動作を尺埋めのために引き延ばさない。

モデル、推論ステップ、生成済みフレーム、区間接続方式は変更していない。終了姿勢の自動検証・再生成は今回追加していない。

## 実生成の確認

変更前後の各プロンプトは1回ずつ、乱数固定なし。計画も生成結果も変わるため、改善率や因果効果の統計的な証明ではない。

| 入力 | 観測 |
| --- | --- |
| 20秒：歩行→右手を振る→腕を下ろしてしゃがむ→6秒保持 | 修正後は腕を下ろす区間が独立し、しゃがんだ後の手が腰より低い位置に残った。最後の6秒の保持中、測定した腰・手の位置は変化なし。 |
| 20秒：待つ→腕を上げる→跳ぶ→両手を振る→お辞儀 | 跳躍中の手の最低位置は変更前に腰より約0.11m下、変更後は左約0.73m／右約0.78m上。ただし最後のお辞儀は依然として弱い。 |
| 30秒：右手→左手→しゃがむ→立つ→6秒保持 | 後半のしゃがみ・立ち上がり・6秒保持を確認。最後は腕が下がり切らず、誤った腕姿勢の保持が残る。 |

20秒2件と30秒1件は、再生済み区間の不変性・予定尺の生成・進捗100%を確認。Node上の再生シミュレーションで途中待機0秒。保存したVRMAを専用ブラウザーのVRMで描画し、正面・側面の画像と軌跡を確認した。初動の短縮・Jevの改善効果は主張しない。

別の文章比較では、最後の区間だけを変えた20秒生成を3種類×2回実施。「上体を腰から深く前に曲げる」という具体的な身体表現で前傾が見られたが、最終姿勢まで維持できる保証はなかった。

成果物：`release/long-motion-before/`、`release/long-motion-after/`、`release/long-motion-30/`、`release/long-motion-captions/`。各`results.json`の`status:passed`は通信・履歴・成果物の検査を表し、動作品質の合格判定ではない。

検証：JavaScript 260件成功、production build成功。今回の実装変更は設計プロンプトのみのため、プロンプトの文言を写した単体テストは追加せず、実モデルの長尺生成を検証に使用した。

## 再実行

```powershell
node tools/ardy-live-session-eval.mjs long-motion-check --only=astra-long-order,astra-long-celebration,astra-long-30
node tools/ardy-live-session-render.mjs long-motion-check
```

ローカルAstraブリッジ（5173）、ARDY（2337）、描画用の専用デバッグブラウザー（9224）が必要。描画ツールは専用ブラウザーを終了する。長尺ケースは通常の評価に自動追加せず、`--only`で明示的に選択する。

完全な長尺安定性には、予定時間が過ぎたことと実際に要求姿勢へ到達したことを分けて扱う必要がある。特に次の区間で部位を固定する前に到達姿勢を検証し、不一致の区間を修正する仕組みが残る課題。今回の変更だけで「長くても破綻しない」とは扱わない。
