# 2026-09-23 モーション生成の再点検

## 一次資料と設計判断

- [ARDY公式実装](https://github.com/nv-tlabs/ardy): テキストを途中で変更できる自己回帰生成と運動学的制約が中心。後処理は任意で速度との交換条件がある。既存の履歴・区間切り替え・移動軸制約を維持し、今回はサンプリング品質を落とさず先読みを調整した。
- [TypeSafeのPrimitives](https://docs.typesafe.ai/primitives): Choiceは選択肢、Scoreは程度、Noulは命題の確率。独立した質問に分け、同じ状態を参照する。[fan-out](https://docs.typesafe.ai/patterns/fan-out)に従い一括解析を維持する。全動作をJevへ設計させる構成にはしない。
- [GPT-6の公式説明](https://developers.openai.com/api/docs/guides/latest-model): Astraは複数段階の作業と文脈を扱う能力を持つ。ただしモーション生成専用モデルとしての保証ではない。[Astraの指示設計記事](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)も踏まえ、固定振り付けを追加せず、完了条件と必要な出力契約を明示する。

## 修正

1. 視線による気づき・準備を、必ず独立した待機区間へ分割する必要はないことをAstraへ伝える。明示された順番・停止・別動作は保持する。
2. ARDYの先読みは従来の基準に加えて、直近の推論・転送・VRMA構築時間から余裕を見積もる。遅い処理には即座に反応し、回復時は徐々に戻す。通常の2秒ホライズンでは上限3秒。モデル・8ステップ設定は変更しない。
3. Jevの視線質問を、明示方向だけでなく状況から根拠のある方向も判定できるよう修正。ただし不明な対象方向や感情に対する固定の仕草は推測しない。Astraの明示視線は上書きしない。
4. 信頼度ゼロの視線・身体スタイルは補助済みとして扱わない。動作が変化すると判定された場合、開始時点のテンポを後続区間に持ち越さない。

## 実測

実Astra（low）と実ARDY（8ステップ）、固定乱数なし。各入力の変更前後は1回ずつで、統計的な速度改善の証明ではない。時刻はNode上のVRMA構築までであり、ブラウザー表示までではない。

| 入力 | 初動・変更前→後 | 再生開始後の停止・前→後 |
| --- | --- | --- |
| 歩いてジャンプ | 8.53→9.85秒 | 0→0秒 |
| 拾って差し出す | 14.03→15.33秒 | 2.59→0秒 |
| 照れながら視線を戻す | 9.36→9.67秒 | 0→0秒 |

初動の改善は確認できていない。拾う動作は待機を含む3区間から2区間になり、そのケースの途中停止がなくなった。主に設計の区間分割が変化した結果であり、先読み変更だけの効果とは解釈しない。

保存したVRMAを専用ブラウザーのVRMで描画し、歩行の後の跳躍・着地、拾う動作、視線指示で腕が動かないことを確認した。一方、差し出す終端では手が下がっており、指定姿勢を保持する精度は未解決。任意動作・正確な接触・回数を保証しない。
