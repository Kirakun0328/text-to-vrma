# Preserving compound motion intent

The reported prompt spreads both arms, pivots half a revolution on one foot,
steps the other foot backward, then lowers the arms and straightens the torso
without losing the braced stance.

## Changes

- Streamed planning now explicitly tracks simultaneous actions, support,
  maintained posture and references to the same foot across phases. It does
  not freeze arms simply because a prior caption requested the desired pose.
- Established planted lower-body support is preserved during subsequent
  upper-body-only motion. Straightening the torso does not imply bringing the
  feet together. Live planning uses medium rather than low reasoning effort.
- Added optional segment `turn: [] | [relativeYawDegrees, pivot]`. Positive is
  left, negative right; pivot 0 is unanchored, 1 left foot, 2 right foot.
  This is an authored geometric constraint, not a keyword-triggered gesture.
- The native engine projects future pelvis heading onto a smooth segment-wide
  arc and, for an explicit pivot, corrects root translation to retain that
  native foot joint's position. Limb articulation is still generated by ARDY.
  Corrected motion is re-encoded into physical history before continuation.
- Both boundaries validate finite angles, allowed pivot values and compatible
  root ownership. Old engines fail explicitly rather than ignore a turn.

## Measurements and limits

The original sample turned about 19.43 degrees during the requested half-turn.
New samples turned 179.99 and 180.01 degrees. These are different stochastic
generations, not identical-seed comparisons; exact-angle behavior is separately
covered by deterministic geometry tests, including chunk partition invariance.

The final plan in `release/pivot-step-support-after/results.json` has three
phases: spread arms while pivoting on left foot; step right foot backward in
the new facing; lower arms/straighten torso with root and legs held.

**This is not full reproduction of the requested motion.** The native foot
anchor does not fully eliminate sliding after retargeting to a differently
proportioned VRM: the observed avatar foot drift was about 7.7 cm (9.2 cm in an
earlier sample). The backward step/braced stance remains weak in the rendered
sample; holding the final lower-body pose preserves the actual generated pose,
not a guaranteed ideal stance. A planted foot joint also does not guarantee
shoe-sole orientation or physically correct balance. No success claim should
equate the passing transport checks with semantic fidelity.

Artifacts: `release/pivot-step-before`, `pivot-step-after`, `pivot-step-auto`,
`pivot-step-support-after`. `tools/pivot-step-audit.mjs` measures actual heading
and rendered-foot drift; `tools/ardy-live-session-render.mjs` renders the VRM.

Validation: 267 JavaScript tests; 4 turn-control, 11 motion-scope and 34 rolling
session Python tests; production build; real Astra/native inference and VRM
inspection. The main engine on port 2337 was restarted with the same settings.
