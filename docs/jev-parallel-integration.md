# Jevとモーション生成の役割分担

Jev解析とAstraの設計は並行開始する。ARDYは最初の設計区間から生成する。追加のLLM呼び出しやJev待機は挟まない。

Astraは各区間の `jev` に補助を許可する項目を指定する。1は既存表情の強さ、2は未指定の視線、4は未指定の身体スタイル。組み合わせ可能で、既定は0。原文が指定した動作、順番、時間、部位、移動軸は変更しない。

区間確定時に解析が到着していれば、項目別信頼度を使って補助する。表情は既存の感情チャンネルと中立の瞬間を保持し、補正幅を制限する。視線は設計済みカーブを上書きしない。身体はテンポ・動きの大きさ・エネルギーだけをARDYへ渡す。動作プリセットや仕草のカタログは使わない。

後から届いた解析は未確定の後続区間にだけ反映する。全区間確定後は今回は使わず、その状態を表示する。API未設定・失敗・低信頼度でも生成は継続する。ARDYのみの経路はCodexを呼ばない。

検証: JavaScript 255件、Python 59件、production buildが成功。並行開始、後続区間への反映、既存の視線・動作・再生済み部分の保持、サーバーで許可項目だけ使うことを検証した。Jev応答はテスト用データであり、実APIを使用した感情推定精度や体感速度の測定は未実施。
