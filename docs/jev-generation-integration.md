# Jevの生成経路への接続

2026-09-21更新。現在の実装を記載する。記事の調査内容と採用理由は [Jev調査とモーション設計](jev-research-motion-design.md) を参照。

## 現在の経路

| 経路 | Jevの使い方 |
| --- | --- |
| Codex + ARDY連続生成 | JevとAstraを並行開始。区間確定時にAstraが許可した表情・視線・身体スタイルだけ補助する。詳細は[並行解析](jev-parallel-integration.md)を参照 |
| ARDYのみ | Codexを呼ばず、原文から直接身体を生成する。Jev解析は並行して進め、未再生区間への従来のスタイル補助を使用する |
| 通常のOpenAI / Claude / Codex | 原文と型を限定した補助JSONを分離し、解析結果を計画へ渡す |
| 画像レビュー・再設計 | 初稿だけでなく評価・修正にも同じ意味情報を保持する |
| ローカルHTTP API | Jevキー設定済みなら省略時も自動利用。明示的な無効設定を尊重する |
| VRMAの顔 | 未設計の顔に限り、独立感情スコアから最大1.2秒の開始表情を補完する。Codexが設計した表情は上書きしない |

Jev解析には既存の期限を維持するが、Codex設計の開始は解析を待たない。
キーがなければ待機せず通常計画へ進む。解析の失敗・時間切れでもCodexの計画は継続する。
総合信頼度が低いことを理由に生成全体を拒否しない。

以前はJevとCodexを同時に開始し、後からARDYの文章条件を変更していた。この方式では、
Jevが最初の計画に使われず、計画済みの動きへ別の解釈が重なる場合があった。現在のCodex経路では行わない。
`plannerOwned: true`では、Astraが明示的に許可した区間の身体スタイルだけ補助できる。感情から別の動作は追加しない。
確定済み区間は変更せず、遅い解析は後続区間にだけ利用する。

## 解析する項目

同じstateに33問をまとめて送る。内訳はChoice 7問、Score 12問、Noul 14問。
質問ごとにアバター・部位・時点を明記し、質問IDや他の質問の回答を暗黙の文脈として使わない。
これは公式の[独立した質問](https://docs.typesafe.ai/primitives)と[一括評価](https://docs.typesafe.ai/patterns/fan-out)の設計に沿う。

| 補助JSON | 意味 |
| --- | --- |
| `body_intent` | `root`・`torso`・`head`・左右の腕・左右の脚について、明示された／身体的に必要な動きである確率 |
| `channel_intent` | 表情と視線が求められている確率 |
| `temporal` | 身体・感情・視線の変化と、動作順序が指定されている確率 |
| `affect` / `affect_end` | 開始時／終了時の独立した5表情スコアと各信頼度 |
| `gaze` / `gaze_end` | 座標方向が明示された開始時／終了時の視線と各信頼度 |
| `emotion`・強度・エネルギー・大きさ・テンポ・対人態度 | 意味や動き方の補助。動作自体の選択にはしない |
| `loop_probability` | 継続的な反復を要求している確率。回数指定や明示的な終了と区別する |
| `probabilities` | 許可したChoice／Score質問の確率分布。任意の文字列や応答フィールドは転送しない |

NoulはYesの確率で、0.5は曖昧さを表す。動作の強度でも、別の信頼度でもない。
Choiceの分布は選択肢間の不確実性であり、そのまま混合感情や複数の身体動作に変換しない。
混合感情には別々のScoreを使う。[Noul](https://docs.typesafe.ai/primitives/noul)・[Choice](https://docs.typesafe.ai/primitives/choice)・[Score](https://docs.typesafe.ai/primitives/score)

不正な回答は項目単位で除外し、残った有効な回答は維持する。利用可能な回答が一つもなければ解析失敗として扱う。
固定仕草カテゴリの`reaction`は質問しない。旧応答に含まれても診断用の読み取りだけにとどめ、動作計画へ転送しない。
生成経路では毎回解析を要求し、解析結果や生成済みクリップの再利用で同じ演技へ固定しない。

## 動きを担当する範囲

Codexの各区間は身体の`body`、頭の`head`、目の`gaze`、表情の`face`を別に設計する。
`body`は新しく動かす関節群の一覧で、仕草の候補リストではない。歩行などに必要な支持・重心・反動もCodexが原文から判断する。
Jevの部位確率をしきい値で切って、機械的に身体を固定しない。

ARDYへ送る本文は対象部位の具体的な動きと必要な制約に絞る。
対人関係、台詞、感情名、目の方向は頭・目・表情の設計側で扱い、不要な腕や脚の動作を誘発する材料にしない。
非対象の関節は実際の直前姿勢を保持し、新規生成時は腕を下ろした基準姿勢を使う。
`body: []`の区間では身体の推論を省略して姿勢を保持する。表情・頭・視線の曲線はそのまま再生する。
全身動作には全7部位を使用でき、任意の動作を既製の仕草へ置換する処理はない。

確定済みの区間は本文・長さ・各曲線を変更せず、末尾へ追加する。
通常の新規生成は独立したセッションで行い、生成中の再入力や明示的な追加修正だけが物理履歴を引き継ぐ。
Codex選択時の計画失敗を、ARDY単独への自動切替で隠さない。

## 記録と制約

- `spec.jevContext`: 型と値を限定した意味情報。
- `spec.jev`: ARDYの文章条件へ追加したフィールドと`bodyApplied`。Codexが設計を担当する経路では追加を行わないため、falseでもJev未使用とは限らない。
- `spec.realtime.jev`: 計画での利用、身体への送信・適用、先行表情、解析状態。
- `spec.realtime.analysisMs`: Jev解析が届くまでの時間。
- `spec.realtime.authoredFromStart`・`plannedSegments`・`plannedDuration`: 最初から設計を使用したか、どこまで区間を受信したか。

これらは入力条件への接続確認であり、アバターが指示を正しく表現できたという品質判定ではない。
今回のJev変更では、実APIを使った日本語の意味解釈精度や通信時間の比較測定は未実施。
初動には解析、Codex設計、身体推論、VRMA変換・読み込みが含まれるため、Jevの公表応答時間をアプリの初動として扱わない。
身体の保持は不要な動きの抑制であり、ARDYが担当する動作の意味・接地・指の細部まで保証するものではない。
音声同期や、実際の映像をJevへ入力して身体の正しさを継続評価する仕組みは未実装。

## 過去の接続検証

以下は旧経路でJevの接続を追加した時点の記録。現在の構成の速度・品質測定とは区別する。

- JavaScript 187件、Python 13件と本番ビルドが通過。
- ブラウザのJev／生成サービスモックで伝達、項目別信頼度、顔補完、表示、履歴、進捗、設定保存を確認。
- 実GPU版ARDYへ合成した意味情報を送り、通常／逐次エンドポイントで入力条件への適用と有限の関節データを確認。
- 2秒・8ステップの単発確認では通常生成とVRMA作成1434ms、逐次の最初のチャンク1055ms／完了1137ms。
  **実Jev通信・Codex計画・ブラウザ表示を含まない接続確認で、現在の構成の応答速度や品質向上の証拠ではない。**
  記録：`release/jev-integration-live-check.json`、生成物：`release/jev-integration-live.vrma`。

過去の詳細は [品質と遅延の記録](realtime-quality-latency.md)、連続生成の操作は [ARDY連続生成](ardy-realtime.md) を参照。
